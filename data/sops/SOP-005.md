# SOP-005: Synthetic & RUM Infrastructure Monitoring Failures

- **Event Type:** Availability / Performance (User Experience)
- **Severity Level:** SEV-1 to SEV-2 (Critical/Major)
- **Impacted Entities:** Web Frontends, Public APIs, Synthetic Monitors

## Diagnostic Steps

1. Open the Synthetic Monitor Execution Details page for the failing location test to check screenshot capture and HTTP response status codes.
2. Review the Waterfalls Analysis to isolate DNS resolution time, TCP connect time, TLS handshake latency, or failing third-party scripts.
3. Check Real User Monitoring (RUM) Session Replays for impacted end-users to confirm if the issue is global or isolated to specific locations, ISPs, or device types.
4. Check external CDN/WAF status dashboards (e.g., Cloudflare, Akamai) to rule out edge-routing failures.

## Remediation Steps

- **CDN / Edge Routing Failover:** Route traffic around degraded CDN locations or update edge routing rules.
- **Third-Party Dependency Bypass:** Disable or fallback non-critical third-party integrations (e.g., analytics tags, chat widgets) failing to respond.
- **Certificate / Credentials Refresh:** Update expired SSL/TLS certificates or authentication tokens configured within synthetic scripts.
